# 03｜用指标而不是感觉做性能判断

## 一张最小实验表

每次实验至少记录：

| 维度 | 示例 |
| --- | --- |
| 模型 | `Qwen/Qwen2.5-0.5B-Instruct` |
| SGLang | 精确版本号 |
| 硬件 | GPU 型号、数量、显存 |
| 输入/输出 | token 长度或数据集 |
| 并发 | `1 / 8 / 32` |
| 缓存 | enabled / disabled |
| 指标 | TTFT、ITL、p50/p99、吞吐量、错误率 |

## 一个简单的判断顺序

1. 先看错误率和完整性：性能提升不能以丢请求为代价。
2. 再看 p99 TTFT：它更接近用户第一次感知到的等待。
3. 再看输出 token 吞吐量：确认系统是否真的处理更多生成工作。
4. 最后结合成本和显存：同一数字在不同硬件上没有同样的工程意义。

仓库里的 `metrics.py` 只做教学用途的 p50/p99 和 token throughput 汇总；真实服务测量应优先使用 SGLang 的 benchmark 输出，并保留原始 JSONL。
